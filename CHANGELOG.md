# Changelog

What each package update changed. Newest first within each package. The
updates arrive through Configure → Updates (or `apt full-upgrade`); the
next images include them.

## riscos-rom (RISC OS itself)

| Version | Date | What changed |
|---|---|---|
| 5.31-24 | 11 Nov 2026 | **Memory behaves as it does on a real RISC OS machine at the edges of dynamic areas:** a new dynamic area goes at the lowest free address, working upwards, as RISC OS does everywhere else, so what lies just past it is normally free and running off its end stops with a data abort, as on a Pi running RISC OS. Before, Linux chose the addresses, top down, each new area directly under the last, so an overrun quietly read or wrote the area made before it: programs with such a fault ran here and stopped on real machines (found comparing native RISC OS with RISC OS on Linux on the same Pi; the web browser project's report). Areas also no longer sit at addresses with the top bit set. **The RAM disc can be up to 2 GB** (it was 128 MB), as on native RISC OS 5.3x (Chris Gransden's report). **A pointer turned off goes off:** a program that hides the pointer (!RDPClient over its window) no longer leaves the last pointer frozen on the screen (Chris Gransden's report). **Room for SWIs without a trap** (with riscos-support 1.0.0041-1): the ROM's busiest SWI calls can go straight to the SWI handler. Built with the DDE 32d; 5.31-20 to 5.31-23 were test builds and weren't packaged. |
| 5.31-19 | 8 Nov 2026 | **Configure's mouse speed works** (with riscos-support 1.0.0034-1 or later): a mouse's movement now reaches RISC OS as movement, so RISC OS applies its mouse speed to it, as on a Pi. It was taken as a position, so the speed was always one pixel per count, slow on a big screen. Tablets (UTM) work as before. **4K in 16 million colours:** the screen can use up to 64 MB, so 3840 x 2160 (and 5K) work in 16 million colours, not only 32 thousand. **Programs that move the pointer** move it on the screen too. Also: a Thumb program's undefined instruction is reported at the right address, and memory checks (OS_Memory 24) answer for PMP areas page by page under QEMU. |
| 5.31-18 | 6 Nov 2026 | **RISC OS no longer stops now and then on the start-up screen as the desktop starts** (mostly under QEMU/UTM, rarely on a Pi): an interrupt landing in one instruction of the port's mode-change code left it looping. **A program's switch back to user mode no longer goes wrong now and then** (UnixLib's mode changes, natively: the program then stops at its next SWI): an interrupt's handlers (ticker routines, ScreenBlanker's, TickerV) could change SPSR_svc under the code they interrupted; the interrupt now keeps it, as it kept r14_svc. Natively 0.2% of such switches made with interrupts on went wrong; now none in 20,000. |
| 5.31-17.1 | 5 Nov 2026 | **RISC OS starts again where it runs under QEMU** (UTM on an Apple Silicon Mac, and other machines that can't run 32-bit ARM code): 5.31-16 and 5.31-17 were installed readable only by root, so protected RISC OS (QEMU, as the user riscos) couldn't load it, and the machine switched off a minute after the start-up screen. The same RISC OS as 5.31-17. Raspberry Pis and the Dev Kit, which run it natively, weren't affected. |
| 5.31-17 | 4 Nov 2026 | **GPIO on a Raspberry Pi 3 or 4:** RISC OS has the Pi's GPIO devices, as RISC OS on the Pi does, working on the board's own GPIO registers (through Linux), so programs that drive the GPIO pins or look for the Pi's GPIO device (the Raspberry Pi edition of ROOL's DDE: its C compiler and assembler) work. Only the pins the board brings out (the 40-pin header) can be changed. Needs riscos-kernel-pi 6.6.78-5 and riscos-support 1.0.0025-1. |
| 5.31-16 | 4 Nov 2026 | **Saving from StrongEd 4.70:** HardDisc4, USB discs and SD cards (IXFS) now have a disc name, ROL, so their full names read `IXFS::ROL.$.…`, like a native disc's `SDFS::RISCOSpi.$.…`. StrongEd 4.70 takes a name with `.$.` in it as a full path and refused every IXFS save ("Don't know where to save"). Names written the old way (`IXFS:$.…`) still work everywhere. |
| 5.31-15 | 4 Nov 2026 | **Finer timing:** the hardware counter that programs use for times finer than a centisecond reloads every centisecond, as on a Pi, not once a second. Programs using UnixLib's clock_gettime (games' frame timing, SDL) get sub-centisecond times instead of 10 ms steps, and the network stack's microsecond times are no longer up to a second out. |
| 5.31-14 | 3 Nov 2026 | *IXRun runs Linux commands as RISC OS's own Linux user (no password, no privileges), through the shell, so a command's name is enough (*IXRun ls -l): it gave ENOENT for any command named without its full path, and always in protected RISC OS. It needs nothing at start-up; the output shows as it comes, Escape stops the command, and a failing one reports its exit status. |
| 5.31-13 | 3 Nov 2026 | **Files over 2GB on HardDisc4 and USB discs** (up to RISC OS's 4GB - 1): IXFS stopped every file at 2GB ("File too large": LanMan98 copies failed there). |
| 5.31-12 | 3 Nov 2026 | **A connection closed by the other end is seen:** `select()` and Socket_Select report it at once instead of waiting out their timeout (ClawsMail's feed and calendar fetches took a minute each). **Saving to HardDisc4 from editors that check the free space first** (StrongEd) works: IXFS's free space always failed. (5.31-11, the free-space fix alone, wasn't released.) |
| 5.31-10 | 2 Nov 2026 | **FileCore discs:** USB sticks and SD cards in RISC OS's own format appear as `SCSI::` drives, with RISC OS Open's SCSISwitch, SCSIFS and SCSIFiler as on a native Raspberry Pi (HForm can format them). Needs riscos-support 1.0.0018-1 and riscos-harddisc 1.0.0018-1. **The keyboard LEDs** (Caps Lock, Num Lock, Scroll Lock) follow RISC OS. (5.31-9, the LEDs alone, wasn't released.) |
| 5.31-8 | 2 Nov 2026 | **Files get the type of their extension** when nothing else says (no `,xxx`, no stored type), as on DOS discs: files on USB discs and files Linux programs wrote show as JPEG, Text, Archive and so on (`photo/jpg` is a JPEG), with their names unchanged. Saving to a USB disc adds `,xxx` only when the name doesn't already say the type. `IXFS#M:` turns it off. Includes 5.31-7's changes (below). |
| 5.31-7 | 2 Nov 2026 | Not packaged on its own (its changes are in 5.31-8). **MbufManager in the ROM**, as in every RISC OS 5 ROM: !Omni's LanManFS and Access work. **Network servers answer their clients:** a connection's first data, sent before the server accepted it, is seen (RDPServer said "server not responding"). |
| 5.31-6 | 1 Nov 2026 | Socket options for GLib programs (SO_TYPE), unknown TCP options refused, Socket_Sendmsg_1 (found by the web browser project). |
| 5.31-5 | 31 Oct 2026 | The Internet module reports version 5.73, so `RMEnsure Internet 5.xx` checks pass: !Omni's LanManager and !Internet start. |
| 5.31-4 | 31 Oct 2026 | Socket_Select returns when its time runs out (TubeSearch and Reel could hang the machine); a locked file can't be renamed. |
| 5.31-3 | 31 Oct 2026 | Proper RISC OS errors from HardDisc4 ("The disc has no more available space", "This item is locked", "This file is already open") instead of Linux's, the Locked attribute obeyed, delete failures no longer lost; physical memory pool areas done by the kernel itself (GCCSDK's ARMEABISupport 1.08). |
| 5.31-2 | 31 Oct 2026 | All the RAM Linux can give RISC OS (up to 4GB) instead of a fixed figure, and the Task Manager's free memory from it; network statistics for NetStats and InetStat; the version reads "RISC OS 5.31-2 (29 Oct 2026)". |
| 1.0.0001-1 | 30 Oct 2026 | The first (ROM build 5.31-1): RISC OS Open's 5.31 nightly of 29 October 2026 merged into Timothy Baldwin's Linux port, which was RISC OS 5.29. ROL-ROM's CHANGELOG has what that took. |
